1. Aim of the Experiment

Symmetric Stream Cipher

To understand and simulate the RC4 (Rivest Cipher 4) Stream Cipher, observing how a secret key initializes a 256-byte state array (KSA) and generates a pseudo-random keystream (PRGA) for byte-by-byte XOR encryption and decryption.

Outcome 1: State Permutation (KSA)

Visualize how the Key-Scheduling Algorithm scrambles the ordered array S[0..255] using a variable-length secret key.

Outcome 2: Keystream Generation (PRGA)

Trace how two moving pointers (i and j) continuously swap elements and extract pseudo-random bytes k.

Outcome 3: Symmetric XOR Reversibility

Verify that XORing ciphertext with the exact same keystream recovers any UTF-8 plaintext without block padding.

2. Theory & Algorithm Breakdown

Designed by Ron Rivest (1987)

20-Second Card-Shuffling Intuition

  • The Deck: Imagine 256 numbered cards (0 to 255) arranged in order inside an array S.
  • Step 1 — KSA (Shuffle): Use your secret key to shuffle those 256 cards into a unique, secret arrangement.
  • Step 2 — PRGA (Draw): For each byte of your message, swap two cards and pick one card's number as your secret keystream byte k.
  • Step 3 — XOR Lock: Combine your message byte with k using XOR (⊕). Because (P ⊕ k) ⊕ k = P, the receiver uses the same key to unlock the exact message.

Phase 1: Key-Scheduling Algorithm (KSA)

Initializes S[i] = i and scrambles S over 256 iterations using key K of byte length L:

for i = 0 to 255: S[i] = i
j = 0
for i = 0 to 255:
  j = (j + S[i] + K[i mod L]) mod 256
  swap(S[i], S[j])

Phase 2: Pseudo-Random Generation (PRGA)

Generates one keystream byte k per data byte and applies bitwise XOR:

i = (i + 1) mod 256
j = (j + S[i]) mod 256
swap(S[i], S[j])
t = (S[i] + S[j]) mod 256
k = S[t]   // Output keystream byte
C = P ⊕ k  // Encrypt (P = C ⊕ k to Decrypt)

Stream Cipher vs. Block Cipher

Feature RC4 (Stream Cipher) AES / DES (Block Ciphers)
Processing Unit 1 byte (8 bits) at a time Fixed blocks (16 bytes for AES, 8 bytes for DES)
Padding Required? No — works on any input length natively Yes (PKCS#7 padding required)
Encrypt / Decrypt Logic Identical function (XOR with keystream) Separate inverse round transformations

Security Note (WEP & TLS Deprecation — RFC 7465)

RC4 was widely used in WEP Wi-Fi and early SSL/TLS. However, statistical biases in its early keystream bytes enabled the FMS (Fluhrer–Mantin–Shamir) key-recovery attack, leading modern TLS 1.3 to replace RC4 with ChaCha20-Poly1305 and AES-GCM.
